# Security review for Orbilap 1.0.1

## Results

- Local candidate from the working tree based on `2b7cd9f`. The release updates tray drawing, time formatting, icon resources and DMG compression. Tauri capabilities, provider request scopes and the updater trust root were reviewed for changes.
- The raw npm audit reports high-severity [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) in `picomatch` 4.0.7. The registry returned 4.0.7 as the latest version and the audit listed no patched version.
- On 2026-11-18 the owner explicitly accepted this finding for Orbilap 1.0.1 only. The production app embeds Vite's generated static files. The app source does not import the matcher and the production output has no matcher references. Vite and Vitest consume repository-controlled build and test configuration, with fixed entry and test patterns. Production account data is handled by the app and is outside those tooling inputs. The risk remains when matching untrusted patterns in the tooling environment.
- The exception applies only to CVE-2026-112366 on the recorded npm lockfile, while npm still reports 4.0.7 as latest. The gate rejects all additional findings and still runs Gitleaks and RustSec.
- Gitleaks found no leaks in the candidate source or local Git history. RustSec reported [RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html) for the app's direct dependency `chrono` 0.4.45. This advisory reports an unmaintained dependency and lists no patched version.
- On 2026-11-18 the owner explicitly accepted this advisory for 1.0.1. The release retains the tested time-handling implementation because RustSec identifies a maintenance warning and switching libraries would require retesting provider reset windows, timestamp parsing and scheduling. The exception covers only this advisory and the reviewed 1.0.1 Cargo.lock. The strict RustSec gate still runs for both supported macOS targets.
- The security gate passed with the two recorded exceptions. Gitleaks found no leaks. RustSec evaluated 351 resolved macOS crates with a freshly fetched database and reported no other findings in that union. Full-lockfile findings outside the union include ZIP extraction issues, GTK and Linux IPC dependency findings, and a withdrawn executor. Review these before supporting any additional targets.
- TypeScript, all 493 Vitest tests, the release workflow tests, offline Cargo check and the locked Rust suite passed. The Rust suite reported 293 passing tests and 10 ignored.
- The local Apple Silicon and Intel DMGs passed image checksum, mount, code signature, version and single-architecture checks. LZMA reduced Apple Silicon from 8,194,113 to 7,039,056 bytes and Intel from 8,435,906 to 7,334,088 bytes. Each mounted executable and icon resource matched the corresponding uncompressed app bundle byte for byte.

## Remaining verification

- Before building the next version, check npm and the advisory for a fix. Apply any available fix to every resolved copy, then rerun the full gate. The 1.0.1 acceptance does not carry forward.
- The `chrono` acceptance expires with 1.0.1. Replace the dependency with a maintained library before a later release or review the finding again. Verify reset windows, timestamp parsing and scheduling during any migration.
- The release workflow verifies the signed updater archives, both DMGs and public downloads from the exact tag. Physical Intel execution and a native end-to-end update installation remain outside the tested scope.
