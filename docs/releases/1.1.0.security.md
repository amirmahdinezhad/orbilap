# Security review for Orbilap 1.1.0

Prepared 2026-11-28 for the next release; publication approval is pending.
Candidate includes all accumulated changes since v1.0.4. Version manifests
are synchronized at 1.1.0. The existing updater public key is unchanged.

## Results

- Frozen pnpm installation, TypeScript check, production frontend build and
  whitespace checks passed.
- Comparable v1.0.4/candidate frontend builds with the same installed toolchain:
  total JS/CSS 846,693 → 865,914 bytes; gzip 236,297 → 247,091 bytes
  (+10,794 bytes, 4.6%). Temporary baseline was removed. New floating UI and
  settings share existing components; no frontend dependency was added.
- Vitest: 551 tests in 49 files passed. Script security suite: 20 passed.
  Release regression suite: 8 passed.
- Locked offline Cargo check passed. Full locked offline Rust rerun passed:
  317 unit tests and 8 integration tests; 10 opt-in live tests ignored.
  Initial concurrent run hit the existing 600ms loopback deadline in the
  Antigravity response-budget test. Isolated and full reruns passed unchanged.
- security:check passed for the resolved union of both macOS targets:
  npm audit reported no known vulnerabilities, Gitleaks 8.30.1 found no leaks
  in working files or 40 commits, cargo-audit 0.22.2 used a fresh database
  containing 1571 advisories. CSP, IPC, updater policy tests passed.
- Other-target lockfile findings remain outside both macOS build trees:
  zip 4.6.1 (RUSTSEC-2026-0548, 0429, 0367, 0368, 0369, 0545), chrono
  0.4.45 (2026-0543), proc-macro-error 1.0.4 (2024-0370), zbus_names
  4.3.4 (2026-0371), zvariant 5.15.0 (2026-0370), zvariant_derive
  5.15.0 (2026-0372), glib 0.18.5 (2024-0429), and yanked
  async-executor 1.14.0. Reassess before adding another supported OS.
- Rechecked CVE-2026-112366: upstream withdrew GHSA-fc5q-39xc-vjpf on
  2026-11-18 as not a security issue. npm reports latest picomatch 4.0.7;
  all resolved copies already use that version. No patch is available or required.
  Source: https://github.com/advisories/GHSA-fc5q-39xc-vjpf
- Reviewed the floating webview's narrow snapshot/action/drag IPC boundary,
  event-listening-only capability, main-only settings options, shared monitor
  cache and private position writer. No second credential probe was added.
- Reviewed native shortcut validation and registration rollback, main-only
  recording/hide commands, private machine preferences and absence of a
  general registration permission in the webview.
- Subscription reconciliation retains existing bounded, identity-checked
  provider requests and private writers. Duplicate-import regressions use
  synthetic credentials; no live account files were read for release testing.
- Repeated security:check on the synchronized 1.1.0 candidate passed.
  Dev restart built 1.1.0 successfully in 7.88s; debug PID 88879 and native
  WebKit PID 89008 were observed with established connections on port 5174.
  Vite returned HTTP 200 and served FloatingUsage; touching it produced the
  17:16:29 frontend HMR update with the native client connected.

## Remaining verification

- Final tagged Apple Silicon and Intel packages, DMGs, archive signatures,
  tamper rejection, checksums, matching binaries and public updater feed
  remain to be verified after approval of the proposed release.
- Native visual acceptance in both themes, focus and pointer behavior,
  reduced motion, provider sign-in/import cancellation and Settings → Updates
  could not be inspected with a tool guaranteed to attach to the existing
  debug PID. Do not launch the installed production app for QA.
  Live browser DOM inspection was not performed; served-source and native
  connection/HMR evidence do not substitute for native visual acceptance.
- Disposable-copy upgrade/install and physical Intel execution have not
  been performed for this candidate. Builds use ad-hoc code signing and
  are not Apple notarized.
- Automated passing checks are bounded evidence, not proof of absence of bugs.
