# Security review for Orbilap 1.0.0

Reviewed on 2026-11-17 for Apple Silicon and Intel macOS 12+.
The owner explicitly authorized publishing version 1.0.0 and replacing the
public Git history with a single current-source snapshot and a fresh version
tag. Prior source, uncommitted changes, security evidence, release metadata and
all eight published assets were preserved in a private backup outside the
repository. Each prior asset matched its published SHA-256 digest.

## Results

- Frozen-lockfile installation, TypeScript, all 493 Vitest tests in 45 files,
  all 18 script tests (including eight release tests), release configuration
  validation and the production frontend build passed. The locked offline Rust
  check and suite passed: 284 library tests and eight integration tests, with
  ten opt-in library tests ignored.
- The security gate passed against the candidate source and unchanged lockfiles
  for both supported macOS architectures. Gitleaks 8.30.1 found no source or
  history leaks, pnpm audit found no known vulnerabilities, and cargo-audit
  0.22.2 checked 351 resolved macOS crates against a fresh RustSec database
  containing 1509 advisories. The exact tagged source is rescanned before the
  final local builds and by the approved publication command.
- Full-lockfile findings outside the macOS dependency union remain: four ZIP
  extraction advisories (RUSTSEC-2026-0429, -0367, -0368, -0369), the GLib
  advisory RUSTSEC-2024-0429, unmaintained proc-macro-error, zbus_names, zvariant
  and zvariant_derive, and yanked async-executor 1.14.0. They do not affect the
  two supported macOS targets. Other operating systems are not released.
- Release builds now use `com.7skylab.orbilap` app-owned storage; debug builds
  use its separate `.dev` sibling and a separate single-instance identifier.
  All saved account repositories, settings, login staging homes, reset records,
  device links and app-owned tools use the same application root. Neither build
  falls back to the old shared `ai.opencode.desktop` store. Existing legacy files
  are preserved for explicit import; they are never migrated automatically.
  There is no background cleanup agent or uninstall service. Deleting only the
  app bundle preserves its data; deleting the dedicated data directory as well
  starts subsequent installations in onboarding.
- The deletion/reinstall regression removes synthetic release settings and all
  three profile indexes while retaining populated dev/legacy stores and a
  synthetic provider login. Fresh settings remain in onboarding with no saved
  profiles or workspace membership. The dev reset regression also preserves the
  new release root. Provider CLI home resolution, external Claude configuration
  references and provider-owned Keychain entries are unchanged. Real account
  files and the owner's private account backups are not changed by release QA.
- The current candidate passed the locked offline Intel check and an Apple
  Silicon production build without bundling. Comparable stripped and ad-hoc
  signed Apple Silicon executables remained 5,091,408 bytes; production frontend
  output remained 984 KiB. Distribution builds retain separate architectures.
- Vite returned HTTP 200 on port 5174; a fresh native dev process and an
  established WebKit connection were confirmed. Touching App.tsx produced a
  fresh HMR update with no browser preview connected to that port.
- CSP, IPC capabilities, credential import permissions, trusted provider
  endpoints, credential redaction and updater policy are covered by the
  automated security/regression suites. These policies and the dependencies
  are unchanged. The retained updater public key matches its private-key
  counterpart outside the repository, whose permissions remain owner-only.
  Provider credentials, private signing material and local QA files are excluded
  from the public snapshot and release artifacts. README preview identities are
  synthetic; image links no longer depend on discarded commit IDs.
- Separate Apple Silicon and Intel DMGs and signed updater archives are built
  locally from the exact tagged commit. The release verifier checks the notes,
  version, bundle identifier, single CPU architecture, strict code signatures,
  DMG integrity, matching DMG/updater binaries, checksums, feed mappings and
  updater signatures. A tampered archive must be rejected before publication.
  Publication uses `pnpm run release:publish --approved`, which verifies the
  downloaded draft and unauthenticated public feed and binary downloads.

## Remaining verification

The app is ad-hoc signed and not Apple notarized. No physical Intel execution
or end-to-end updater installation has been performed. There is no older public
version for an upgrade test; replacing an existing 1.0.0 installation requires
manually installing the matching DMG because same-version builds are not offered
as updates.

Native UI automation timed out while resolving the unbundled dev executable.
Direct visual confirmation of onboarding, Settings/Updates and provider sign-in,
switching and reset redemption is outside the verified scope. Existing provider
CLI homes remain shared for discovery and explicit account activation; isolated
Orbilap stores do not isolate those external applications. These previously
reported manual limits remain accepted by the owner's renewed explicit 1.0.0
publication request. No production account mutation is part of release QA.

The owner explicitly renewed approval to rebuild, replace and publish 1.0.0
with this storage correction and a fresh single-commit public history. This
approval retains the reported native UI, physical Intel and update-installation
limits. The previous source and release are privately backed up before their
replacement; final distributables are rebuilt from the newly tagged commit.

Automated passes are bounded evidence and do not prove the absence of bugs.
