# Security review for Orbilap 1.0.2

## Results

- GitHub withdrew [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) for `picomatch` on 2026-11-18. npm listed 4.0.7 as the latest release. This candidate removes the 1.0.1 exception and uses the standard npm audit.
- The candidate replaces the app's direct `chrono` dependency with `time` 0.3.55, which was already in the lockfile. It removes the 1.0.1 exception for [RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html). The gate uses Cargo's feature-resolved test and production trees for each macOS architecture. This includes the production custom protocol and host build dependencies. The old metadata query included an optional `serde_with` edge to `chrono` that is inactive in both builds.
- Reviewed the changed timestamp paths for provider quota resets, credential expiry, saved profiles, device usage and switching deadlines. The timestamp tests cover numeric offsets, the existing UTC output and pre-epoch milliseconds. Timestamp conversion does not grant permissions or expand the endpoints that receive credentials.
- Release notes render as React text. The development-only preview uses synthetic data. Updater permissions, production CSP, the HTTPS release feed and signing key are unchanged. Download and installation remain separate actions.
- The npm audit found no known vulnerabilities. Gitleaks 8.30.1 found no leaks in the candidate source or Git history. Cargo Audit 0.22.2 loaded 1,533 RustSec advisories during review and found no warnings or vulnerabilities in the macOS build union. The full lockfile still reports inactive packages including ZIP, Chrono, GTK and Linux IPC dependencies.
- TypeScript, 493 Vitest tests, release and security script tests, locked offline Cargo check and the locked Rust suite passed. Rust reported 295 passing tests and 10 ignored.
- The owner requested a same-version rebuild on 2026-11-19. The prior release metadata, assets and Git history were backed up locally and the asset checksums verified. The new change uses the shared secondary button for update checks and restores its keyboard focus ring. It leaves update requests, signature verification and installation behavior unchanged. The GitHub advisory API still reported the `picomatch` advisory withdrawn with no patched version, and the npm audit reported no known vulnerabilities.

## Remaining verification

- Native credential import, external sign-in with real providers and physical Intel execution remain outside the verified scope. The original 1.0.2 candidate passed a signed Tauri updater installation on a disposable Apple Silicon 1.0.1 bundle. The rebuild requires fresh artifact verification. Existing 1.0.2 installations require a manual DMG reinstall.
